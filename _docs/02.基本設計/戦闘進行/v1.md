# ターン 詳細設計書

## 1. 目的

本設計書では、戦闘における1ターンの開始から終了までの状態、処理順序、行動管理、行動順決定について定義する。

攻撃、魔法、防御、状態異常そのものの効果計算については、それぞれ個別の詳細設計で定義する。

## 2. ターンの責務

ターンは、1ターン内で発生する以下の情報と進行を管理する。

- ターン番号
- ターン開始
- 戦闘参加者の行動選択
- 行動対象の確定
- 行動順の決定
- 行動済み状態の管理
- 行動可能状態の確認
- 全行動終了の判定
- ターン終了処理への移行

ターン自身は以下を担当しない。

- 攻撃ダメージの計算
- 魔法効果の計算
- HP・MPそのもののルール
- 装備補正の計算
- 状態異常の具体的効果計算
- 敵の行動選択ロジック
- 戦闘全体の勝敗管理

## 3. ターンの識別

ターンは戦闘内で一意となるターン番号を持つ。

```text
TurnNumber
```

最初のターンを1とする。

以降、

```text
1
2
3
4
...
```

と増加する。

TurnNumberは1以上の整数とする。

ターンにグローバルなIDは付与しない。

同一戦闘内ではTurnNumberによってターンを識別する。

## 4. ターン状態

ターンは以下の状態を持つ。

```text
NotStarted
SelectingActions
OrderingActions
ExecutingActions
Ending
Completed
```

### NotStarted

ターン生成直後の状態。

まだターン処理を開始していない。

### SelectingActions

戦闘参加者の行動と対象を決定している状態。

### OrderingActions

すべての必要な行動選択が完了し、行動順を決定している状態。

### ExecutingActions

決定した順番に従って行動している状態。

### Ending

すべての通常行動が終了し、ターン終了処理を実行している状態。

毒などのターン終了時効果はこの段階で処理する。

### Completed

ターン処理が完全に終了した状態。

Completedになったターンを再度実行することはできない。

## 5. 状態遷移

基本的な状態遷移は以下とする。

```text
NotStarted
    ↓
SelectingActions
    ↓
OrderingActions
    ↓
ExecutingActions
    ↓
Ending
    ↓
Completed
```

一度進んだ状態を前の状態へ戻すことはできない。

例えば、

```text
ExecutingActions
↓
SelectingActions
```

への遷移は許可しない。

## 6. ターン開始

ターン開始時点で、生存している戦闘参加者をそのターンの参加者として確定する。

対象となるのは主人公側および敵側の双方である。

死亡している戦闘参加者はターン参加者に含めない。

ターン開始後、状態を以下へ変更する。

```text
NotStarted
↓
SelectingActions
```

## 7. ターン参加者

1ターンに参加可能な人数は最大8人とする。

```text
主人公側 最大4人
敵側     最大4人
```

ターンは戦闘参加者Entityそのものを所有せず、戦闘参加者を識別する情報を保持する。

概念上は以下とする。

```text
TurnParticipant
    ParticipantId
    SelectedAction
    ActionOrder
    ActionConsumed
    ConsumedReason
```

## 8. 行動選択

ターン開始時に、ターンへ参加しているすべての戦闘参加者について行動を確定する。

行動実行開始後に、新しい行動を選択することはできない。

つまり、

```text
全員の行動選択
↓
行動順決定
↓
行動実行
```

の順序を必須とする。

## 9. 対象選択

対象を必要とする行動については、行動選択時に対象も確定する。

概念的には以下の情報を保持する。

```text
SelectedAction
    ActorId
    ActionType
    TargetId
```

対象を必要としない行動の場合、TargetIdは不要とする。

具体的にどの行動が対象を必要とするかについては、行動の詳細設計で定義する。

## 10. 行動選択後の変更

一度行動選択が完了した戦闘参加者について、ExecutingActions状態になった後の行動変更は許可しない。

例えば、

```text
勇者
こうげき
対象: スライムA
```

を選択した後、行動順決定後に、

```text
対象: スライムB
```

へ変更することはできない。

選択対象が行動実行前に死亡した場合の具体的な行動結果については、行動の詳細設計で定義する。

ただし、結果が成功・失敗のどちらであっても、その戦闘参加者の1ターン分の行動は消費する。

## 11. 行動順

行動順は戦闘参加者のすばやさによって決定する。

数値の高い戦闘参加者から順番に行動する。

例：

```text
勇者       すばやさ 50
スライムA  すばやさ 30
僧侶       すばやさ 20
```

の場合、

```text
1. 勇者
2. スライムA
3. 僧侶
```

となる。

## 12. 同一すばやさ

すばやさが同じ戦闘参加者が複数存在する場合、乱数によって順番を決定する。

例：

```text
勇者       50
戦士       50
スライムA  20
```

勇者と戦士について乱数による順番決定を行う。

## 13. 同一すばやさ用乱数

同一すばやさの参加者ごとに、そのターン専用の乱数値を生成する。

乱数値は十分広い値域を使用する。

実装上は64bit整数相当の値域を使用する。

概念上、

```text
SpeedTieBreaker
```

として扱う。

例：

```text
勇者
Speed = 50
TieBreaker = 918273645

戦士
Speed = 50
TieBreaker = 182736455
```

この場合、TieBreakerの大小によって順番を確定する。

TieBreakerはターンごとに新しく生成する。

前ターンの値は使用しない。

## 14. 乱数衝突

同一すばやさの参加者間でTieBreakerまで同じ値となった場合、該当する参加者について再度乱数を生成する。

一意の値が得られるまで繰り返す。

そのため、最終的な行動順に同順位は存在しない。

## 15. 行動順の比較規則

行動順は以下の優先順位で決定する。

```text
第1条件
すばやさの高い順

第2条件
同一すばやさの場合はTieBreaker
```

概念的には、

```text
Speed DESC
TieBreaker DESC
```

で並べる。

TieBreakerの昇順・降順自体にゲーム上の意味はないため、実装全体で一方に統一する。

本設計では降順とする。

## 16. 乱数生成の責務

Turn自身が具体的な乱数生成方式を知る必要はない。

乱数を取得できる仕組みを外部から利用する。

概念的には以下とする。

```csharp
public interface IRandomSource
{
    ulong Next();
}
```

本番では通常の乱数生成を使用する。

テストでは任意の値を返せる乱数生成処理を使用できるものとする。

これにより行動順を再現可能なテストとする。

## 17. 行動順決定完了

すべての戦闘参加者について一意の行動順が決定した時点で、

```text
OrderingActions
↓
ExecutingActions
```

へ遷移する。

行動実行開始後は行動順を変更しない。

## 18. 1ターン1行動

戦闘参加者は1ターンにつき1回のみ行動機会を持つ。

各ターン参加者について、

```text
ActionConsumed
```

を管理する。

初期状態は、

```text
false
```

とする。

行動機会を消費した場合、

```text
true
```

となる。

一度trueになったActionConsumedを同一ターン内でfalseへ戻してはならない。

## 19. 行動消費

以下の場合に1回分の行動を消費したものとする。

### 正常に行動した

通常攻撃、魔法、防御などを実行した。

### 行動が失敗した

MP不足などにより行動の効果が発生しなかった。

### 麻痺した

麻痺によって行動できなかった。

### 行動対象が無効だった

行動自体が成立しなかった場合でも、行動機会は消費する。

具体的な失敗条件は各行動の詳細設計で定義する。

## 20. 行動前の死亡

ターン開始時点では生存していた参加者が、自身の行動順になる前にHP0となる可能性がある。

例：

```text
1. 勇者がスライムAを攻撃
2. スライムAの行動
```

勇者の攻撃によってスライムAが死亡した場合、

```text
スライムA
```

の選択済み行動は実行しない。

Turn上ではその行動枠を終了扱いとする。

## 21. 行動消費理由

行動を終了した理由を識別できるものとする。

以下を定義する。

```text
Executed
DeadBeforeAction
Paralyzed
Failed
ConsumedByEscape
```

### Executed

選択した行動を実行した。

### DeadBeforeAction

行動前に死亡したため実行しなかった。

### Paralyzed

麻痺によって行動できなかった。

### Failed

選択した行動を試みたが成立しなかった。

MP不足などが該当する。

### ConsumedByEscape

逃げる処理によって、そのターンの残りの行動機会を失った。

## 22. 行動実行順

ExecutingActions状態では、ActionOrderの先頭から順番に処理する。

各参加者について以下を確認する。

```text
1. すでに行動済みか
2. 生存しているか
3. 行動可能か
4. 選択した行動を実行
5. 行動済みにする
6. 戦闘終了条件を確認
```

行動済みの参加者を再度処理することはない。

## 23. 麻痺との関係

麻痺状態の参加者についても、ターン上の行動順は通常どおり存在する。

自身の行動順になった時点で麻痺が有効な場合、選択した行動を実行しない。

その行動機会を消費する。

```text
ConsumedReason = Paralyzed
```

とする。

麻痺の残り回数の管理および解除については状態異常の詳細設計で定義する。

## 24. 逃げるとの関係

逃げるが実行された場合、逃走そのものは必ず失敗する。

逃げるを実行した参加者は通常どおり1回の行動を消費する。

その時点で、まだ行動していないすべての参加者についても行動済みとする。

```text
ConsumedReason = ConsumedByEscape
```

とする。

その後、通常の行動実行を終了し、ターン終了処理へ移行する。

すでに行動済みの参加者については状態を変更しない。

## 25. 戦闘終了との関係

各行動終了後、戦闘が終了条件を満たしたか確認する。

主人公側または敵側の全員が死亡した場合、その時点で残りの行動を実行しない。

例：

```text
勇者
↓
敵最後の1体を撃破
↓
敵全滅
```

の場合、それ以降に行動予定だった主人公側参加者についても行動しない。

戦闘終了時は、通常のターン終了時効果を実行せず、戦闘終了処理へ移行する。

ターンについては戦闘終了によって終了したことを記録する。

## 26. 通常のターン終了条件

以下のいずれかを満たした場合、通常行動フェーズを終了する。

```text
すべてのターン参加者の行動枠が終了した
```

または、

```text
逃げるによって残り行動が消費された
```

この場合、

```text
ExecutingActions
↓
Ending
```

へ遷移する。

## 27. ターン終了時処理

Ending状態では、ターン終了時に発生する効果を処理する。

現時点では、少なくとも毒を対象とする。

毒状態の生存者について、ターン終了時効果を適用する。

具体的なダメージ処理は状態異常の詳細設計に従う。

## 28. ターン終了時の死亡

毒などのターン終了時効果によってHPが0となる場合がある。

ターン終了時効果をすべて適用した後、戦闘終了条件を確認する。

戦闘が終了する場合は、その結果を戦闘側へ通知する。

## 29. ターン完了

すべてのターン終了処理が終了した場合、

```text
Ending
↓
Completed
```

へ遷移する。

Completed状態になったTurnについて、それ以上の変更を許可しない。

次ターンでは新しいTurnを生成する。

## 30. ターン終了理由

Turnが終了した理由を保持できるものとする。

```text
Normal
EscapeAttempt
BattleEnded
```

### Normal

すべての行動およびターン終了処理を正常に終了した。

### EscapeAttempt

逃げるによって残りの行動が終了した。

戦闘自体は継続する。

### BattleEnded

ターン途中またはターン終了処理によって戦闘終了条件を満たした。

## 31. Turnの保持情報

Turnが最低限保持する情報を以下とする。

```text
Turn
 ├ TurnNumber
 ├ State
 ├ Participants
 ├ ActionOrder
 └ EndReason
```

TurnParticipantは以下を保持する。

```text
TurnParticipant
 ├ ParticipantId
 ├ SelectedAction
 ├ Speed
 ├ TieBreaker
 ├ ActionOrder
 ├ ActionConsumed
 └ ConsumedReason
```

Speedは行動順決定時に使用した値とする。

## 32. すばやさ値の確定タイミング

行動順決定に使用するすばやさは、OrderingActionsへ移行した時点の値を使用する。

行動順決定後に能力値が変化しても、そのターンの行動順は変更しない。

つまり、

```text
行動順確定
↓
すばやさ変化
```

が発生した場合、その変化は次ターンの行動順から反映する。

## 33. C#概念モデル

Turnは概念上、以下のような構造とする。

```csharp
public sealed class Turn
{
    public int TurnNumber { get; }
    public TurnState State { get; private set; }
    public TurnEndReason? EndReason { get; private set; }

    private readonly List<TurnParticipant> _participants;
}
```

ターン状態は以下とする。

```csharp
public enum TurnState
{
    NotStarted,
    SelectingActions,
    OrderingActions,
    ExecutingActions,
    Ending,
    Completed
}
```

終了理由は以下とする。

```csharp
public enum TurnEndReason
{
    Normal,
    EscapeAttempt,
    BattleEnded
}
```

行動消費理由は以下とする。

```csharp
public enum ActionConsumedReason
{
    Executed,
    DeadBeforeAction,
    Paralyzed,
    Failed,
    ConsumedByEscape
}
```

## 34. TurnParticipant概念モデル

```csharp
internal sealed class TurnParticipant
{
    public ParticipantId ParticipantId { get; }

    public SelectedAction? SelectedAction { get; private set; }

    public int Speed { get; private set; }

    public ulong? TieBreaker { get; private set; }

    public int? ActionOrder { get; private set; }

    public bool ActionConsumed { get; private set; }

    public ActionConsumedReason? ConsumedReason { get; private set; }
}
```

TurnParticipantはTurn内部でのみ使用する。

戦闘参加者Entityそのものとは別の概念とする。

## 35. Turnの不変条件

Turnは常に以下を満たす。

```text
TurnNumberは1以上
```

```text
同一ParticipantIdを2つ以上保持しない
```

```text
Completedから他状態へ遷移しない
```

```text
ExecutingActions開始時点ですべての必要な行動が選択済み
```

```text
行動順は重複しない
```

```text
1参加者につき行動消費は最大1回
```

```text
ActionConsumed = true の場合
ConsumedReasonが必ず存在する
```

```text
一度消費した行動を未消費へ戻さない
```

## 36. 操作

Turnが提供する主要な操作は概念上以下とする。

```text
Start
```

ターンを開始する。

```text
SelectAction
```

参加者の行動を登録する。

```text
DetermineActionOrder
```

すばやさと乱数から行動順を決定する。

```text
ExecuteNext
```

次に行動すべき参加者を処理する。

```text
ConsumeAction
```

参加者の行動を消費済みにする。

```text
BeginEnding
```

ターン終了処理へ移行する。

```text
Complete
```

ターンを完了する。

実際のメソッド分割については実装時に責務を確認して確定する。

## 37. 禁止する操作

以下を許可しない。

```text
ターン開始前の行動選択
```

```text
同一参加者の行動を複数回登録
```

```text
全員の行動選択完了前の行動実行
```

```text
行動順決定前の行動実行
```

```text
行動済み参加者の再行動
```

```text
Completed状態の変更
```

```text
行動実行開始後の行動順変更
```

## 38. テスト観点

### ターン開始

TurnNumberが1以上で生成できる。

0以下のTurnNumberを許可しない。

死亡者がターン対象にならない。

### 行動選択

生存参加者全員の行動を登録できる。

同一参加者へ2回行動を登録できない。

行動選択完了前にExecutingActionsへ移行できない。

### 行動順

すばやさが高い順になる。

すばやさが同じ場合、乱数によって順番が決まる。

同じ乱数値が発生した場合、再生成する。

毎ターン異なるTieBreakerを利用する。

最大8参加者について一意の順番を生成できる。

### 行動消費

正常な行動で1回消費される。

失敗した行動でも1回消費される。

麻痺でも1回消費される。

死亡済みとなった参加者の行動が実行されない。

同じターンで2回行動できない。

### 逃げる

逃げる実行後、未行動参加者がすべて行動済みになる。

逃げる後に通常行動が実行されない。

戦闘自体は終了しない。

### ターン終了

全員の行動終了後にEndingへ移行する。

ターン終了時効果を処理できる。

終了処理後にCompletedになる。

Completed後に処理を再開できない。

### 戦闘終了

ターン途中で一方が全滅した場合、残りの通常行動を実行しない。

戦闘終了時に不要な次ターンを開始しない。

## 39. 他の詳細設計との境界

Turnは「いつ・誰が・どの順番で・1回行動するか」を管理する。

具体的な行動内容については別設計とする。

今後の詳細設計との関係は以下とする。

```text
Turn
  ↓
Action
  ├ Attack
  ├ Defense
  ├ Mera
  ├ Hoimi
  ├ Escape
  └ Item
```

また、

```text
Turn
  ↓
BattleParticipant
```

から生存状態、すばやさ、状態異常など必要な情報を参照する。

Turn自身にHP、MP、攻撃力、守備力などのキャラクター状態は保持しない。
