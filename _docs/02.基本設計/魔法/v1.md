# 魔法 詳細設計書

## 1. 目的

本設計書では、戦闘中に使用する魔法について、使用条件、MP消費、対象、効果、失敗条件、および処理結果を定義する。

現時点で扱う魔法は以下の2種類とする。

```text
メラ
ホイミ
```

ターン管理、戦闘参加者のHP・MP管理、状態異常、装備については、それぞれ別の詳細設計で定義する。

## 2. 魔法の責務

魔法処理は以下を担当する。

```text
魔法の種類の判定
使用可能MPの確認
魔法対象の確認
MP消費
魔法効果の実行
魔法実行結果の生成
```

魔法処理自身は以下を担当しない。

```text
行動順の決定
ターン開始・終了
戦闘終了判定
装備補正
状態異常処理
敵の行動選択
```

## 3. 魔法種別

魔法は大きく以下の種別に分類する。

```text
Attack
Recovery
```

### Attack

敵へダメージを与える魔法。

現時点ではメラが該当する。

### Recovery

対象のHPを回復する魔法。

現時点ではホイミが該当する。

## 4. 使用可能な魔法

現時点では以下の魔法を定義する。

| 魔法 | 種別 | 消費MP | 効果 |
|---|---|---:|---|
| メラ | 攻撃魔法 | 2 | 敵1体へダメージ |
| ホイミ | 回復魔法 | 4 | 対象のHPを15回復 |

## 5. 魔法の基本情報

各魔法は最低限以下の値を持つ。

```text
Name
Type
MpCost
```

概念上、

```text
Magic
 ├ Name
 ├ Type
 └ MpCost
```

とする。

魔法そのものはIDを持たない。

## 6. メラ

メラは攻撃魔法とする。

```text
Name   = Mera
Type   = Attack
MpCost = 2
```

敵側の生存している戦闘参加者1体を対象とする。

メラを正常に使用した場合、使用者のMPを2消費する。

対象へ魔法ダメージを与える。

具体的なダメージ量は現時点では未確定とする。

## 7. ホイミ

ホイミは回復魔法とする。

```text
Name   = Hoimi
Type   = Recovery
MpCost = 4
```

生存している回復対象1体へ使用する。

正常に使用した場合、使用者のMPを4消費する。

対象のHPを15回復する。

```text
RecoveryAmount = 15
```

## 8. 魔法対象

対象を必要とする魔法については、ターン開始時の行動選択時に対象を確定する。

概念上、

```text
SelectedMagicAction
 ├ ActorId
 ├ Magic
 └ TargetId
```

として扱う。

魔法実行開始後に対象を変更することはできない。

## 9. メラの対象

メラの対象は敵対陣営の戦闘参加者1体とする。

以下は対象として認めない。

```text
使用者自身
同一陣営
死亡している戦闘参加者
存在しない戦闘参加者
```

## 10. ホイミの対象

ホイミは生存している戦闘参加者を対象とする。

死亡状態の戦闘参加者へホイミを使用することはできない。

本システムには蘇生の概念が存在しないため、

```text
HP = 0
```

の対象をホイミによって復活させることはできない。

ホイミを使用できる陣営範囲については、戦闘参加者と行動選択の仕様に従う。

## 11. MP確認

魔法実行時には、実際に魔法を発動する前に現在MPを確認する。

使用者の現在MPが消費MP以上である場合のみ魔法を発動できる。

メラの場合、

```text
CurrentMp >= 2
```

ホイミの場合、

```text
CurrentMp >= 4
```

を必要とする。

## 12. MP不足

現在MPが必要MPを下回る場合、魔法は発動しない。

例：

```text
現在MP = 1
メラ必要MP = 2
```

の場合、

```text
魔法失敗
```

とする。

MP不足時にはMPを消費しない。

ただし、魔法を使用しようとした行動そのものは消費する。

したがって、

```text
行動消費 = true
MP消費 = 0
魔法効果 = なし
```

となる。

## 13. MP消費

魔法が正常に発動可能な場合、魔法効果の実行に伴ってMPを消費する。

概念上、

```csharp
caster.ConsumeMp(magic.MpCost);
```

とする。

Magic処理がMPプロパティを直接書き換えることはしない。

MPの下限保証はBattleParticipant側で行う。

## 14. MP下限

MPが0未満になることは許可しない。

必要MPが不足している場合には魔法そのものを発動しないため、

```text
MP < 0
```

となる処理は発生しない。

## 15. 魔法実行時の対象再確認

対象はターン開始時に選択するが、実際の魔法実行時にも対象状態を確認する。

ターン中に他の参加者の行動によって対象状態が変化している可能性があるためである。

## 16. 対象が死亡していた場合

魔法実行時点で対象が死亡している場合、その魔法は失敗とする。

別の対象へ自動的に変更しない。

この場合、行動は消費する。

対象不在による失敗では魔法を発動しない。

したがってMPも消費しない。

```text
ActionConsumed = true
MpConsumed = 0
Effect = none
```

## 17. メラの基本処理フロー

メラは以下の順序で処理する。

```text
1. 使用者の状態確認
2. 対象の状態確認
3. 対象が敵であることを確認
4. MP確認
5. MP消費
6. メラのダメージ量を決定
7. 対象へダメージ適用
8. 実行結果生成
9. 行動消費
```

## 18. ホイミの基本処理フロー

ホイミは以下の順序で処理する。

```text
1. 使用者の状態確認
2. 対象の状態確認
3. MP確認
4. MP消費
5. HP回復量を決定
6. 対象へHP回復を適用
7. 実行結果生成
8. 行動消費
```

## 19. ホイミの回復量

ホイミの基本回復量は固定値15とする。

```text
HealAmount = 15
```

対象の現在HPが、

```text
CurrentHp + 15
```

によって最大HPを超える場合、最大HPまで回復する。

例：

```text
CurrentHp = 90
MaxHp     = 100

ホイミ
↓
CurrentHp = 100
```

実際の回復量は10となる。

## 20. 最大HP時のホイミ

対象のHPがすでに最大HPの場合でも、対象として有効であるならホイミを実行可能とする。

この場合、

```text
ActualRecovery = 0
```

となる。

魔法は正常に発動したものとして扱い、MPを4消費する。

行動も消費する。

## 21. 回復処理の責務

Magic処理自身がHPを書き換えることはしない。

概念上、

```csharp
target.RecoverHp(15);
```

とする。

最大HPを超えない保証についてはBattleParticipant側が担当する。

## 22. メラのダメージ

メラによる具体的なダメージ計算式は現時点では未定義とする。

魔法詳細設計上は、

```text
MeraDamage
```

という結果を取得し、対象へ適用する。

今後、以下を別途確定する。

```text
固定ダメージとするか
能力値を使用するか
乱数を使用するか
最低ダメージを設定するか
```

## 23. メラと守備力

メラは魔法攻撃であるため、通常攻撃で使用する物理守備力による計算をそのまま使用しない。

現時点ではメラのダメージ式が未確定であるため、守備力を使用するかどうかも未確定とする。

## 24. メラと防御

通常攻撃用の「防御」効果については、

```text
相手の攻撃力を1/4にする
```

という物理攻撃用の仕様である。

したがって、現時点ではメラに通常攻撃用防御効果を適用しない。

魔法に対する防御仕様を追加する場合は別途定義する。

## 25. 魔法の命中判定

現時点では魔法に攻撃ミスの仕様を設けない。

通常攻撃に存在する、

```text
0 ～ 0.1の場合ミス
```

という判定はメラには適用しない。

有効な対象が存在し、必要MPを満たしている場合、メラは発動する。

## 26. 魔法の会心

現時点では魔法に会心の一撃を設けない。

会心判定は通常攻撃のみの仕様とする。

## 27. 属性

本システムでは現時点で属性を扱わない。

そのため、

```text
炎属性
氷属性
雷属性
```

などの属性判定は行わない。

メラという名称であっても、本設計上は属性による弱点・耐性計算を行わない。

## 28. 耐性

魔法耐性の概念は現時点では設けない。

そのため、

```text
魔法ダメージ半減
魔法無効
炎耐性
```

などの処理は行わない。

## 29. 使用者が死亡している場合

自身の行動順になる前に使用者が死亡していた場合、魔法は実行しない。

MPも消費しない。

この場合のターン上の行動消費理由は、

```text
DeadBeforeAction
```

とする。

この判定はTurnとの連携によって行う。

## 30. 麻痺時

魔法を選択済みであっても、自身の行動時に麻痺によって行動不能となった場合、魔法を実行しない。

MPも消費しない。

行動は1回消費する。

```text
MpConsumed = 0
Effect = none
ConsumedReason = Paralyzed
```

とする。

## 31. MagicResult

魔法実行結果はValue Objectとして表現する。

概念上以下を保持する。

```text
MagicResult
 ├ MagicName
 ├ ResultType
 ├ CasterId
 ├ TargetId
 ├ MpConsumed
 ├ Damage
 ├ Recovery
 └ FailureReason
```

## 32. 魔法結果種別

以下を定義する。

```text
Success
Failed
```

### Success

魔法が正常に発動した。

### Failed

魔法を発動できなかった。

## 33. 魔法失敗理由

以下を定義する。

```text
InsufficientMp
CasterDead
TargetDead
InvalidTarget
```

### InsufficientMp

必要MPが不足している。

### CasterDead

魔法実行前に使用者が死亡している。

### TargetDead

対象が魔法実行前に死亡している。

### InvalidTarget

選択した対象が、その魔法で指定できない対象である。

## 34. メラ成功結果

概念的には以下とする。

```text
MagicName   = Mera
ResultType  = Success
MpConsumed  = 2
Damage      = 計算された値
Recovery    = 0
```

## 35. ホイミ成功結果

例としてHPを15すべて回復できた場合、

```text
MagicName   = Hoimi
ResultType  = Success
MpConsumed  = 4
Damage      = 0
Recovery    = 15
```

最大HPによって実際の回復量が10だった場合、

```text
Recovery = 10
```

とする。

## 36. MP不足結果

例えばメラ使用時にMPが1しか存在しない場合、

```text
MagicName     = Mera
ResultType    = Failed
MpConsumed    = 0
Damage        = 0
Recovery      = 0
FailureReason = InsufficientMp
```

とする。

## 37. Magic定義

魔法そのものの定義はValue Objectとして扱えるものとする。

概念上、

```csharp
public sealed record Magic(
    string Name,
    MagicType Type,
    int MpCost);
```

とする。

魔法種別は、

```csharp
public enum MagicType
{
    Attack,
    Recovery
}
```

とする。

## 38. 魔法定義の不変条件

Magicは以下を満たす。

```text
Nameが存在する
MpCostは0以上
Typeが有効
生成後に変更されない
```

現在使用する魔法については、

```text
Mera
Attack
2
```

```text
Hoimi
Recovery
4
```

を定義する。

## 39. MagicAction

ターン中に実際に選択された魔法行動は、Magicそのものとは別概念とする。

概念上、

```text
MagicAction
 ├ Magic
 └ TargetId
```

とする。

Magicは、

```text
メラとは何か
```

を表し、

MagicActionは、

```text
このターンに
誰にメラを使うか
```

を表す。

## 40. 責務の分離

概念的な関係は以下とする。

```text
Turn
 ↓
MagicAction
 ↓
Magic
 ↓
BattleParticipant
```

Turnは、

```text
いつ魔法を使うか
```

を管理する。

MagicActionは、

```text
どの魔法を誰に使うか
```

を表す。

Magicは、

```text
魔法の種類と基本仕様
```

を表す。

BattleParticipantは、

```text
HP
MP
生存状態
```

を管理する。

## 41. C#概念モデル

概念上、魔法実行は以下のような形を想定する。

```csharp
public sealed class MagicAction
{
    public MagicResult Execute(
        BattleParticipant caster,
        BattleParticipant target);
}
```

ただし、具体的なクラス構成はドメインモデル全体との整合性を確認して確定する。

## 42. Magic処理の禁止事項

Magic自身は以下を行わない。

```text
ターンを進める
```

```text
次の行動者を決定する
```

```text
戦闘終了を確定する
```

```text
装備を変更する
```

```text
BattleParticipantのHPやMPを直接代入する
```

```text
無効になった対象を別対象へ自動変更する
```

## 43. テスト観点

### メラ

MP2以上で使用できる。

正常使用時にMPを2消費する。

MP1以下では発動しない。

MP不足でも行動を消費する。

敵1体を対象にできる。

死亡している対象には発動しない。

対象死亡時に別の敵へ自動変更しない。

通常攻撃のミス判定を使用しない。

通常攻撃の防御計算を使用しない。

### ホイミ

MP4以上で使用できる。

正常使用時にMPを4消費する。

HPを15回復する。

最大HPを超えない。

実際に増えたHP量を結果として取得できる。

最大HP状態でも使用可能である。

最大HP状態で使用した場合もMPを4消費する。

死亡者を回復できない。

### MP不足

MP不足時にMPを消費しない。

効果が発生しない。

1ターン分の行動を消費する。

### 行動前死亡

使用者が死亡している場合、魔法を実行しない。

MPを消費しない。

### 対象死亡

行動選択後に対象が死亡した場合、魔法を実行しない。

MPを消費しない。

別対象へ変更しない。

### 麻痺

麻痺によって行動不能の場合、魔法を実行しない。

MPを消費しない。

行動を消費する。

## 45. 未確定事項

現時点で魔法について残る主要な未確定事項は以下とする。

```text
メラのダメージ計算式
```

加えて、ホイミについて以下を確定すると対象ルールが完全に決まる。

```text
ホイミで自分自身を対象にできるか
```

```text
ホイミの対象を味方陣営のみに限定するか
```

この3点を決定すれば、メラ・ホイミについて実装可能な詳細仕様が完成する。
