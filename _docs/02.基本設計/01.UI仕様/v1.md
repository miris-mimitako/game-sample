# Presentation層 追加・変更仕様

## 1. UI方針

本アプリケーションのユーザーインターフェースは、コマンドプロンプト上で動作するConsole Applicationのみとする。

以下のGUI技術は使用しない。

- Windows Forms
- WPF
- WinUI
- Blazor
- Webブラウザ
- その他GUIフレームワーク

ユーザーからの入力およびゲーム状態の出力は、標準入力・標準出力によって行う。

## 2. Presentationプロジェクト

Presentation層は以下のプロジェクトとする。

```text
Game.Presentation.Console
```

アプリケーションのEntry Pointもこのプロジェクトに配置する。

```text
Game.Presentation.Console
 └ Program.cs
```

## 3. Presentation層の責務

Console Presentationは以下を担当する。

```text
ゲーム開始操作

戦闘データファイルの指定

現在の戦闘状態表示

行動候補表示

行動入力受付

対象候補表示

対象入力受付

行動結果表示

ターン結果表示

勝敗表示
```

戦闘ルールそのものはPresentation層に実装しない。

## 4. 起動時処理

アプリケーション起動後、戦闘開始に利用するファイルを指定する。

概念的な操作例は以下とする。

```text
Battle Game

戦闘データファイルを入力してください。

> ./data/battle01.json
```

入力されたファイルパスをApplication Layerへ渡す。

Presentation側でJSONを解析しない。

## 5. 戦闘開始表示

戦闘開始後、参加者情報を表示する。

例：

```text
==============================
戦闘開始
==============================

[味方]

1. 勇者
HP 100 / 100
MP 30 / 30

2. 僧侶
HP 80 / 80
MP 50 / 50

[敵]

1. スライムA
HP 30 / 30

2. スライムB
HP 30 / 30
```

表示形式はPresentation側の責務とする。

## 6. ターン開始表示

ターン開始時には現在のターン番号を表示する。

```text
==============================
TURN 1
==============================
```

その後、生存している主人公側参加者について順番に行動を入力する。

## 7. 行動選択

選択可能な行動を番号で表示する。

例：

```text
勇者の行動を選択してください。

1. こうげき
2. ぼうぎょ
3. まほう
4. アイテム
5. にげる

> 1
```

入力された番号をApplication Layerで使用可能なCommandへ変換する。

## 8. 対象選択

対象が必要な行動の場合、対象候補を表示する。

通常攻撃の例：

```text
攻撃対象を選択してください。

1. スライムA  HP 30 / 30
2. スライムB  HP 30 / 30

> 2
```

これにより、

```text
Action = Attack
Target = スライムB
```

という入力をApplication Layerへ渡す。

## 9. 魔法選択

魔法を選択した場合、利用可能な魔法を表示する。

例：

```text
魔法を選択してください。

1. メラ   MP 2
2. ホイミ MP 4

> 1
```

メラの場合は敵を対象候補として表示する。

ホイミの場合は回復対象候補を表示する。

対象の妥当性そのものはDomain側で保証する。

## 10. 敵行動

敵側についてはConsoleからユーザー入力を要求しない。

敵の行動決定処理から取得した結果を使用する。

敵の行動選択ロジックはPresentation層に実装しない。

## 11. 行動実行結果表示

ターン実行結果をApplication Layerから受け取り、順番に表示する。

例：

```text
勇者のこうげき！

スライムAに18のダメージ！

スライムAのこうげき！

勇者に6のダメージ！
```

ミスの場合、

```text
勇者のこうげき！

しかし攻撃はミスした！
```

と表示する。

## 12. 魔法結果表示

メラの場合、

```text
勇者はメラを唱えた！

スライムAに20のダメージ！
```

ホイミの場合、

```text
僧侶はホイミを唱えた！

勇者のHPが15回復した！
```

MP不足の場合、

```text
勇者はメラを唱えようとした！

しかしMPが足りない！
```

と表示する。

具体的な文言はPresentationの表現であり、Domainでは保持しない。

## 13. 状態異常表示

毒によるダメージが発生した場合、

```text
勇者は毒のダメージを受けた！

10のダメージ！
```

と表示する。

麻痺によって行動できなかった場合、

```text
勇者は麻痺して動けない！
```

と表示する。

Domainからは状態異常処理の結果を受け取り、Presentation側で文章へ変換する。

## 14. 死亡表示

HPが0になった場合、

```text
スライムAを倒した！
```

または対象に応じた死亡メッセージを表示する。

死亡判定そのものはPresentationでは行わない。

例えば以下は禁止する。

```csharp
if (participant.Hp == 0)
{
    Console.WriteLine("死亡");
}
```

Applicationから取得した結果を基に表示する。

## 15. ターン終了時表示

ターン終了後、現在の戦闘状態を表示できるものとする。

例：

```text
==============================
TURN 1 END
==============================

勇者
HP 72 / 100
MP 28 / 30

僧侶
HP 80 / 80
MP 46 / 50

スライムA
死亡

スライムB
HP 18 / 30
```

戦闘が継続する場合は次のターンへ移行する。

## 16. 戦闘終了表示

敵側が全滅した場合、

```text
==============================
VICTORY
==============================

戦闘に勝利しました。
```

主人公側が全滅した場合、

```text
==============================
DEFEAT
==============================

戦闘に敗北しました。
```

と表示する。

## 17. Console入力

Consoleからの入力は文字列として受け取る。

概念上、

```csharp
var input = Console.ReadLine();
```

を利用する。

入力値を直接Domainへ渡さず、PresentationまたはApplication用の入力型へ変換してから渡す。

## 18. 不正入力

以下のようなConsole入力はPresentation上の入力エラーとして扱う。

```text
数字を要求している箇所への文字入力

存在しない選択番号

空入力
```

例：

```text
1. こうげき
2. ぼうぎょ

> abc

入力が正しくありません。
もう一度入力してください。
```

再入力を要求する。

これはゲーム上の行動失敗ではないため、ターンを消費しない。

## 19. ドメイン上の行動失敗との違い

Console入力ミスとゲーム上の行動失敗を明確に分離する。

### Console入力ミス

```text
存在しない番号
数値変換失敗
空入力
```

Presentationで再入力する。

行動はまだ確定していない。

### ドメイン上の失敗

```text
MP不足
対象が行動前に死亡
麻痺
```

選択済み行動の結果として発生する。

1ターン分の行動を消費する。

## 20. ConsoleとDomainの分離

以下の依存を禁止する。

```text
Battle.Domain
↓
Console.ReadLine
```

```text
Battle.Domain
↓
Console.WriteLine
```

DomainからConsole APIを直接利用してはならない。

Application LayerについてもConsole固有処理を持たせない。

Consoleとの接続はPresentationプロジェクトだけで行う。

## 21. Console用ViewModel

Consoleへ表示する情報はApplication Layerから取得したDTOを利用する。

概念上、

```text
BattleStateDto
 ├ TurnNumber
 ├ PlayerParticipants
 ├ EnemyParticipants
 └ BattleStatus
```

などを利用する。

Console側はDTOを表示用文字列へ変換する。

## 22. プロジェクト構造

Presentationを含めた構成は以下とする。

```text
src/

  Game.Presentation.Console/
    Program.cs

    Battle/
      BattleConsoleController.cs

    Input/
      ConsoleInputReader.cs

    Output/
      BattleConsoleRenderer.cs

  Battle/
    Battle.Domain/
    Battle.Application/
    Battle.Infrastructure/

  BattleSetup/
    BattleSetup.Application/
    BattleSetup.Infrastructure/
```

## 23. ConsoleInputReader

Consoleからユーザー入力を取得する責務を持つ。

概念上、

```text
ConsoleInputReader
```

は、

```text
数値入力
文字列入力
選択肢入力
```

などを担当する。

ゲームルールを持たない。

## 24. BattleConsoleRenderer

戦闘状態や行動結果をConsoleへ表示する責務を持つ。

概念上、

```text
BattleConsoleRenderer
```

が、

```text
参加者表示
HP表示
MP表示
ターン表示
攻撃結果表示
魔法結果表示
状態異常表示
勝敗表示
```

を担当する。

## 25. BattleConsoleController

Console操作とApplication Use Caseをつなぐ。

概念的な流れは以下とする。

```text
ConsoleInputReader
        ↓
BattleConsoleController
        ↓
Battle.Application
        ↓
Battle Domain
        ↓
Application Result
        ↓
BattleConsoleRenderer
        ↓
Console
```

Controllerに戦闘ルールを記述しない。

## 26. Program.cs

Program.csはComposition Rootとして扱う。

主な責務は、

```text
依存関係の構築

Infrastructure実装の登録

Application Serviceの生成

Console処理開始
```

とする。

ゲームロジックはProgram.csに記述しない。

## 27. アプリケーション全体フロー

```text
dotnet run
     ↓
Program.cs
     ↓
戦闘ファイル入力
     ↓
Battle Setup
     ↓
Battle生成
     ↓
Consoleに戦闘状態表示
     ↓
行動入力
     ↓
対象入力
     ↓
Application
     ↓
Battle Domain
     ↓
結果取得
     ↓
Console表示
     ↓
次ターン
     ↓
戦闘終了
     ↓
Consoleに勝敗表示
     ↓
Application終了
```
