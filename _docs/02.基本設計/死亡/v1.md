# 死亡状態 詳細設計書

## 1. 目的

本設計書では、戦闘参加者の死亡状態について、死亡条件、死亡後の行動制限、ターンとの関係、状態異常との関係、および戦闘終了判定との境界を定義する。

本システムでは蘇生を扱わない。

## 2. 死亡の基本方針

死亡は独立した状態異常として扱わない。

戦闘参加者の現在HPが0である場合、その戦闘参加者を死亡状態とする。

```text
CurrentHp = 0
↓
死亡
```

現在HPが1以上の場合は生存状態とする。

```text
CurrentHp >= 1
↓
生存
```

したがって、死亡状態を表現するための独立したフラグは保持しない。

## 3. 死亡判定

死亡判定は現在HPから導出する。

概念上は以下とする。

```csharp
public bool IsDead => CurrentHp == 0;
```

生存判定は以下とする。

```csharp
public bool IsAlive => CurrentHp > 0;
```

`IsDead`や`IsAlive`自体を変更可能な値として保持しない。

## 4. 死亡状態を別途保持しない理由

以下のような状態を発生させないためである。

```text
CurrentHp = 0
IsDead = false
```

または、

```text
CurrentHp = 50
IsDead = true
```

死亡状態をHPから導出することで、死亡状態とHPの不整合を防止する。

## 5. HP下限

現在HPは0未満にならない。

例えば、

```text
CurrentHp = 5
Damage = 20
```

の場合、

```text
CurrentHp = 0
```

とする。

```text
CurrentHp = -15
```

とはしない。

HP下限の保証はBattleParticipant自身の責務とする。

## 6. 死亡発生条件

現在HPがダメージによって0になった場合に死亡する。

死亡原因として少なくとも以下を扱う。

```text
通常攻撃
魔法攻撃
毒
その他のHP減少効果
```

死亡原因によって死亡状態そのものの扱いは変化しない。

## 7. ダメージによる死亡

通常攻撃などによってHPが0になった場合、そのダメージ処理完了時点から死亡状態となる。

例：

```text
CurrentHp = 20
Damage = 25
↓
CurrentHp = 0
↓
死亡
```

死亡判定をターン終了まで遅延させない。

## 8. ターン途中の死亡

ターン開始時には生存していた戦闘参加者が、自身の行動前に死亡する場合がある。

例：

```text
行動順

1. 勇者
2. スライム
```

勇者の攻撃によってスライムのHPが0になった場合、

```text
スライム
↓
死亡
↓
行動不可
```

となる。

スライムがターン開始時に行動を選択済みであっても、その行動は実行しない。

## 9. 死亡時の行動消費

ターン開始後、自身の行動前に死亡した場合、そのターンの行動枠は終了したものとして扱う。

Turn側では、

```text
ActionConsumed = true
ConsumedReason = DeadBeforeAction
```

として扱う。

ただし、死亡者自身が何らかの行動を実行したわけではない。

## 10. 死亡者の行動選択

ターン開始時点ですでに死亡している戦闘参加者については、行動選択を行わない。

また、Turnの行動対象者として含めない。

```text
死亡
↓
行動選択対象外
```

とする。

## 11. 死亡者の行動順

ターン開始時点ですでに死亡している戦闘参加者について、行動順を生成しない。

ターン開始後に死亡した場合は、そのターンで既に確定している行動順自体を組み替えない。

該当する行動枠を実行せずに終了する。

## 12. 死亡後の禁止行動

死亡状態の戦闘参加者は、以下を実行できない。

```text
通常攻撃
防御
魔法
アイテム
逃げる
その他の戦闘行動
```

死亡状態の戦闘参加者から行動を要求された場合、処理を実行しない。

## 13. 死亡者のMP

死亡によってMPを0に変更しない。

例えば、

```text
HP = 0
MP = 20
```

という状態は許可する。

死亡は、

```text
行動不能
```

を意味するものであり、

```text
MP消失
```

を意味しない。

ただし本システムでは蘇生しないため、その戦闘中にMPを再利用することはない。

## 14. 死亡者の装備

死亡によって装備を解除しない。

死亡前に保持していた、

```text
武器
防具
アクセサリー
```

はそのままBattleParticipantに保持する。

死亡は装備状態を変更する契機とはしない。

## 15. 死亡と状態異常

死亡した場合、毒や麻痺などの状態異常を保持していても、それらの効果を処理しない。

例えば、

```text
HP = 0
Poison = true
```

の場合、ターン終了時に毒ダメージを発生させない。

## 16. 死亡と麻痺

麻痺状態の戦闘参加者が行動前に死亡した場合、死亡判定を優先する。

判定順序は以下とする。

```text
死亡判定
↓
麻痺判定
↓
行動
```

死亡している場合、麻痺効果は処理しない。

麻痺の残り回数も減少させない。

Turn側では、

```text
ConsumedReason = DeadBeforeAction
```

とする。

```text
ConsumedReason = Paralyzed
```

とはしない。

## 17. 死亡と毒

毒ダメージによってHPが0になった場合も死亡する。

例：

```text
CurrentHp = 7
PoisonDamage = 10
↓
CurrentHp = 0
↓
死亡
```

その後、その戦闘参加者について追加の状態異常処理は行わない。

## 18. 死亡者への通常攻撃

死亡状態の戦闘参加者を通常攻撃の有効対象とはしない。

ターン開始時に対象を選択した後、攻撃実行までに対象が死亡していた場合、

```text
AttackResult = Failed
FailureReason = TargetDead
```

とする。

別の対象へ自動変更しない。

## 19. 死亡者への攻撃魔法

死亡状態の戦闘参加者を攻撃魔法の有効対象とはしない。

メラの対象が実行前に死亡していた場合、

```text
MagicResult = Failed
FailureReason = TargetDead
```

とする。

MPは消費しない。

行動は消費する。

## 20. 死亡者への回復魔法

死亡状態の戦闘参加者へホイミを使用することはできない。

```text
HP = 0
↓
ホイミ対象不可
```

本システムには蘇生が存在しないため、回復処理によって死亡状態から生存状態へ戻すことはできない。

## 21. 死亡者へのHP回復

BattleParticipantは死亡状態の場合、通常のHP回復を受け付けない。

概念上、

```csharp
participant.RecoverHp(...)
```

を死亡者に対して実行しても、生存状態へ復帰させない。

死亡からの復帰には蘇生という別のドメインルールが必要となるが、本システムでは蘇生を定義しない。

## 22. 死亡状態の不可逆性

1回の戦闘中に死亡状態となったBattleParticipantは、生存状態へ戻らない。

```text
Alive
↓
Dead
```

は許可する。

```text
Dead
↓
Alive
```

は許可しない。

本システムではこの状態遷移を不可逆とする。

## 23. 死亡状態遷移

戦闘参加者の生命状態は以下とする。

```text
Alive
  ↓
HPが0
  ↓
Dead
```

DeadからAliveへの遷移は存在しない。

## 24. 死亡と防御

防御状態の戦闘参加者が死亡した場合、その後、防御状態による効果を利用することはない。

死亡者は攻撃対象にならないため、防御効果を評価する必要がない。

ターン終了時に防御状態を解除する処理が存在する場合も、死亡状態そのものには影響しない。

## 25. 死亡と行動対象

ターン開始時に死亡している参加者は、通常の行動対象候補から除外する。

例えば、敵4体のうち1体が死亡している場合、

```text
敵A 生存
敵B 生存
敵C 死亡
敵D 生存
```

攻撃対象として提示可能なのは、

```text
敵A
敵B
敵D
```

とする。

## 26. 全滅判定

一方の陣営に所属するすべての戦闘参加者が死亡した場合、その陣営を全滅状態とする。

概念上、

```text
全参加者について IsDead = true
```

である場合に全滅とする。

麻痺などによって一時的に全員が行動不能であっても、全滅とはしない。

## 27. 戦闘終了との関係

主人公側または敵側が全滅した場合、戦闘終了条件を満たす。

ただし、BattleParticipant自身は戦闘終了を決定しない。

BattleParticipantが提供するのは、

```text
自分が死亡しているか
```

という情報までとする。

複数のBattleParticipantを評価して、

```text
敵側が全滅した
主人公側が全滅した
```

と判断する責務はBattle側に置く。

## 28. 死亡直後の戦闘終了判定

通常行動によって死亡が発生した場合、その行動完了後に戦闘終了条件を確認する。

例：

```text
敵残り1体
↓
勇者が攻撃
↓
敵HP = 0
↓
敵全滅確認
↓
戦闘終了
```

全滅した場合、そのターンに残っている行動は実行しない。

## 29. ターン終了時死亡

毒などのターン終了時効果によって死亡が発生する場合がある。

この場合、

```text
ターン終了効果
↓
死亡
↓
全滅確認
↓
戦闘終了判定
```

とする。

## 30. BattleParticipantの責務

BattleParticipantは死亡について以下を担当する。

```text
現在HPの保持
HP下限0の保証
ダメージ受付
HP0の判定
生存・死亡状態の提供
死亡状態でのHP回復禁止
```

## 31. Turnの責務

Turnは死亡について以下を担当する。

```text
ターン開始時の死亡者除外
行動直前の死亡確認
死亡者の行動停止
DeadBeforeActionとして行動枠を終了
```

Turn自身がBattleParticipantを死亡状態へ変更することはしない。

## 32. Attack・Magicの責務

AttackやMagicは、対象へ効果を適用する前に対象の生存状態を確認する。

ただし、

```text
HPを0にする
死亡フラグを立てる
```

といった処理を直接行わない。

ダメージはBattleParticipantへ渡す。

概念上、

```csharp
target.TakeDamage(damage);
```

とする。

## 33. Battleの責務

Battleは複数のBattleParticipantの死亡状態を確認して以下を判定する。

```text
主人公側全滅
敵側全滅
戦闘継続
```

BattleParticipant自身は勝敗を判断しない。

## 34. TakeDamage

BattleParticipantはダメージを受ける操作を提供する。

概念上、

```csharp
TakeDamage(int damage)
```

とする。

ダメージは0以上とする。

現在HPを超えるダメージが指定された場合も、HPを0まで減少させる。

## 35. TakeDamage結果

ダメージ適用結果を値として返せるものとする。

概念上、

```text
DamageResult
 ├ RequestedDamage
 ├ ActualDamage
 ├ RemainingHp
 └ BecameDead
```

とする。

例：

```text
CurrentHp = 10
Damage = 30
```

の場合、

```text
RequestedDamage = 30
ActualDamage = 10
RemainingHp = 0
BecameDead = true
```

とする。

## 36. BecameDead

`BecameDead`は今回のダメージによって、

```text
生存
↓
死亡
```

へ遷移したかを示す。

すでに死亡している対象へダメージ処理そのものを実行しないため、

```text
Dead
↓
Dead
```

を`BecameDead = true`とは扱わない。

## 37. HP回復

生存しているBattleParticipantのみHP回復可能とする。

概念上、

```csharp
RecoverHp(int amount)
```

とする。

```text
CurrentHp = 0
```

の場合、通常回復処理を許可しない。

## 38. 死亡状態の表現

死亡専用の以下のようなVOは作成しない。

```text
DeathStatus
DeadStatus
DeathState
```

また、

```csharp
bool IsDead;
```

を変更可能なフィールドとして保持しない。

現在HPをSingle Source of Truthとする。

## 39. CharacterとBattleParticipant

死亡はBattleParticipant上の戦闘状態として扱う。

Characterそのものが永久に死亡したことを意味しない。

概念上、

```text
Character
↓
今回の戦闘
↓
BattleParticipant
↓
HP = 0
↓
この戦闘では死亡
```

とする。

戦闘終了後のCharacterに死亡状態を引き継ぐかについては、本設計の対象外とする。

## 40. C#概念モデル

概念上、BattleParticipantは以下のようになる。

```csharp
public sealed class BattleParticipant
{
    public int CurrentHp { get; private set; }

    public bool IsAlive => CurrentHp > 0;

    public bool IsDead => CurrentHp == 0;

    public DamageResult TakeDamage(int damage)
    {
        // HP下限を保証する
    }

    public RecoveryResult RecoverHp(int amount)
    {
        // 死亡者は回復不可
        // 最大HPを超えない
    }
}
```

具体的な型やメソッド構成はBattleParticipantの詳細設計で確定する。

## 41. 不変条件

BattleParticipantは死亡状態に関して常に以下を満たす。

```text
CurrentHp >= 0
```

```text
CurrentHp <= MaxHp
```

```text
CurrentHp = 0
なら
IsDead = true
```

```text
CurrentHp > 0
なら
IsAlive = true
```

```text
IsDeadとIsAliveが同時にtrueにならない
```

```text
死亡後に通常回復によってHPを1以上にしない
```

## 42. 禁止事項

死亡状態について以下を禁止する。

```text
死亡状態を手動でtrue/falseへ変更する
```

```text
HPが存在するのに死亡状態だけを別管理する
```

```text
死亡者が通常行動する
```

```text
死亡者へ通常回復を適用する
```

```text
死亡者を通常攻撃や通常魔法の有効対象とする
```

```text
死亡によって装備を自動解除する
```

```text
死亡によってMPを自動的に0へ変更する
```

```text
BattleParticipant自身が戦闘勝敗を判断する
```

## 43. テスト観点

### 生存判定

HP1で生存状態となる。

HP最大値で生存状態となる。

HP0で死亡状態となる。

### ダメージ

HP100の参加者が10ダメージを受けてHP90となる。

HP10の参加者が10ダメージを受けてHP0となる。

HP10の参加者が20ダメージを受けてもHP0となる。

HPが負数にならない。

### 死亡遷移

HP1から1ダメージで死亡する。

死亡した瞬間から行動不能となる。

### ターン

ターン開始時に死亡している参加者は行動選択対象にならない。

行動順確定後に死亡した参加者は行動しない。

死亡による未実行行動がDeadBeforeActionとなる。

### 状態異常

死亡者に毒ダメージを適用しない。

死亡者の麻痺回数を減少させない。

毒によるダメージで死亡できる。

### 回復

生存者はHPを回復できる。

死亡者はホイミで回復できない。

死亡者へ通常回復を行っても復活しない。

### MP・装備

死亡してもMPは保持される。

死亡しても武器を保持する。

死亡しても防具を保持する。

死亡してもアクセサリーを保持する。

### 対象判定

死亡者を新規の攻撃対象として選択できない。

選択済み対象が死亡した場合、攻撃が失敗する。

選択済み対象が死亡した場合、魔法が失敗する。

## 44. 設計上の確定事項

死亡状態について以下を確定する。

```text
死亡条件はHP = 0
```

```text
死亡状態を独立したフラグとして保持しない
```

```text
HPを死亡状態のSingle Source of Truthとする
```

```text
HPは0未満にならない
```

```text
死亡した時点から行動できない
```

```text
行動前死亡では選択済み行動を実行しない
```

```text
死亡者はターン開始時の行動選択対象にならない
```

```text
死亡者を通常の攻撃対象としない
```

```text
死亡者をホイミで回復できない
```

```text
蘇生は存在しない
```

```text
死亡状態は1戦闘中不可逆
```

```text
死亡してもMPを0にしない
```

```text
死亡しても装備を解除しない
```

```text
死亡者には毒・麻痺などの状態異常効果を処理しない
```

```text
死亡判定は麻痺判定より優先する
```

```text
全滅判定および勝敗判定はBattleの責務とする
```

## 45. 他設計との関係

死亡状態を中心とした責務関係は以下とする。

```text
Attack / Magic / Poison
        ↓
    Damage
        ↓
BattleParticipant
        ↓
      HP = 0
        ↓
      IsDead
        ↓
   ┌────┴────┐
   ↓         ↓
 Turn      Battle
   ↓         ↓
行動停止   全滅判定
```

この構造により、死亡というドメインルールをBattleParticipantに集約しながら、ターン管理や勝敗判定との責務を分離する。
